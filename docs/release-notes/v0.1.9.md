# FluentQtWidgets v0.1.9

This maintenance release fixes transient overlap during expandable-card animations and incorrect Fluent scroll-bar handle sizes after layout changes.

## Highlights

- `ExpandSettingCard` now reveals its content by animating the visible height. Its internal scroll position stays at zero, and the parent layout updates before resized cards and their siblings are painted.
- Rapidly reversing an expand/collapse animation continues from the current visible height, keeping the card position and content stable.
- Fluent overlay scroll bars synchronize their range, page step, and single step after Qt finishes layout. This covers initial display, viewport resizing, and changing content sizes.
- Deferred scroll-bar synchronization safely stops if the partner scroll area or native scroll bar has been destroyed.
- Added regression tests for animation frames in scrolled containers, rapid reversals, overlay scroll-bar sizing, and partner lifetime.

## Integration

When a resizable `QScrollArea` hosts a layout of expandable cards, set the content layout's size constraint to `QLayout::SetMinAndMaxSize`. This keeps the content's minimum size and the outer scroll range current as cards change height:

```cpp
auto *content = new QWidget;
auto *layout = new QVBoxLayout(content);
layout->setSizeConstraint(QLayout::SetMinAndMaxSize);
// Add cards to layout.
area->setWidgetResizable(true);
area->setWidget(content);
```

This is a setting for the application's content layout; the library does not change every containing scroll area's layout constraint.
